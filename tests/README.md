# tests/ — testy integracyjne

Testy integracyjne `*.itest.ts` uruchamiane na realnym PostgreSQL przez
**testcontainers** (Docker). Pokrywają krytyczne przepływy, których nie da się
sprawdzić bez bazy (tenant-scope, zapisy transakcyjne, kaskady, autoryzacja).

- Uruchamia je właściciel pod Dockerem: `npm run test:itest`
  (vitest z dłuższym timeoutem; filtr ścieżki `tests`).
- Testy jednostkowe (bez DB) leżą przy kodzie jako `app/**/*.test.ts` i lecą
  przez `npm run test:unit` — `tests/` ich nie zawiera.

| Plik | Zakres |
|---|---|
| `consultations.itest.ts` | Repo konsultacji (`app/lib/consultations.ts`): tworzenie z punktami, izolacja tenantów (obcy trener/podopieczny → brak dostępu), guard własności przy zmianie statusu punktu, podmiana punktów przy edycji, kaskadowe usuwanie, liczniki. |
| `google-sync.itest.ts` | Synchronizacja Google Calendar (`app/lib/google/sync.ts`) na realnej bazie, z zamockowanym `@googleapis/calendar`: `syncUpsertOne` (insert z `conferenceDataVersion:1`/`sendUpdates:"all"`/uczestnikiem, persystencja `google_event_id`+`meetingUrl`; błąd Google nie rzuca i nie rusza stanu natywnego), repo-helpery `listGoogleEventIdsForPair`/`listCancelledGoogleEventIds`, `syncCancelAllForPair`, `syncCancelStaleSchedule`, oraz **`syncBackfillPair`** — wstawia brakujące, `patch`-uje istniejące (regresja stref: `dateTime` bez „Z" + `timeZone: Europe/Warsaw`), pomija przeszłe i odwołane, nie patchuje właśnie wstawionych, no-op bez połączenia Google. |
| `progression-tenant-scope.itest.ts` | Tenant-scope Progresji (`app/lib/progression.ts`): `findTraineeOfTrainer` (obcy trener → null, właściwy → podopieczny), `listProgressionExercises` (lista P_A bez logów innego podopiecznego), `getExerciseProgression` (dane tylko z logów P_A, cudze ćwiczenie → null), `getProgressionComparison` (serie + pominięte). |
| `lists-sort-filter-tenant-scope.itest.ts` | Tenant-scope + poprawność sort/filtr/szukajki dla list: `listLogsForTrainee` (sort=hardest/easiest/sets_desc, video=with/without, q, izolacja traineeB), `countLogsForTrainee` (video+q), `listClientsForTrainer` (sort=most_sessions + paginacja, q, plan=with/without, izolacja trenerów), `listConsultationsForTrainee` (open=with_open, q, sort=most_open/date_asc, izolacja traineeB). |
| `rpe-toggle.itest.ts` | Przełącznik RPE per ćwiczenie (`exercises.tracksRpe`): zapis `difficulty = NULL` dla ćwiczenia bez RPE, sesja mieszana liczy `avgDifficulty` tylko z ocenionych serii, `getExerciseProgression` zwraca `avgRpeInRange = null` gdy brak ocen, `getEffortBalance` pomija sesje bez RPE (nie rzuca i zwraca liczbę). |
| `skills.itest.ts` | Umiejętności/awanse (`app/lib/skills.ts`, `app/lib/skill-progression.ts`): tenant-scope (obcy trener → null/`SkillError`), pełny cykl create→addVariation×3→reorder→setStartingLevel→awans→regres + `getSkillMapForTrainee` (poprawny `currentVariationId` = najnowsze zdarzenie, historia), `UNIQUE(exercise_id)` („exercise taken"), `ON DELETE RESTRICT` przy `removeVariation` („referenced"), guardy `recordAdvancement` („no start"/„same level"). |
| `skill-tier.itest.ts` | Tier umiejętności (`app/lib/skills.ts`): zapis/odczyt tieru, `DEFAULT 'basic'` z migracji, tenant-scope (obcy trener nie odczyta ani nie nadpisze), twarda walidacja „prereq nie z wyższego tieru" w `addPrerequisite` (równy i niższy przechodzą), filtr pickera `listAssignablePrerequisites`, oraz kolizja po zmianie tieru — `updateSkill` przechodzi, a `listConflictingPrerequisites` ją raportuje. |
| `onboarding-payment.itest.ts` | Onboarding płatności (OB-3): po rejestracji z zaproszenia z kwotą `setMonthlyAmount` tworzy wiersz `coaching_subscriptions` (status `none`, `amountGrosze`, `stripePriceId`) dla pary trener↔podopieczny; para bez wywołania → `getSubscriptionForPair` = null; tenant-scope (obcy trener → null). Klient Stripe mockowany. |
| `upload-wideo.itest.ts` | Trasa zasobowa `/upload/wideo` (realny Postgres + zapis na dysk w katalogu tymczasowym): `trainerId`/`uploadedBy`/`kind` brane z SESJI i stałej w kodzie, a pola `trainerId`/`kind` dorzucone do `FormData` są IGNOROWANE; trener odbity (trasa tylko dla podopiecznych); niezgodne magic-bytes → 400 i zero wierszy w `files`; brak pliku → 400; odpowiedź to czysty JSON parsowalny gołym `JSON.parse` (konsumuje ją XHR, nie React Router). |
| `workout-video-ids.itest.ts` | **Walidacja identyfikatorów nagrań przy zapisie** (`assertOwnedUnclaimedVideos`) — rdzeń bezpieczeństwa rozdzielonego uploadu. Kluczowy przypadek: nagranie INNEGO podopiecznego TEGO SAMEGO trenera musi zostać odrzucone (sam `trainer_id` tego nie wyłapie, chroni dopiero `uploaded_by`). Dalej: obcy tenant, zły rodzaj pliku, nagranie już podpięte, nieistniejące id, duplikat w jednym żądaniu, odrzucenie CAŁEGO zapisu gdy choć jedno id jest złe. |
| `orphan-sweeper.itest.ts` | Sweeper nagrań-sierot (`sweepOrphanSetVideos`): kasuje `set_video` po karencji i niepodpięte (wiersz + blob), NIE rusza podpiętych, świeższych niż karencja ani plików innego rodzaju. `deleteFileBlob` mockowany — testujemy wybór wierszy, nie dysk. |
| `stripe-pause.itest.ts` | Pauza/wznowienie subskrypcji (RD-1): `pauseSubscription` ustawia status `paused` i woła Stripe `subscriptions.update` z `pause_collection.behavior === "void"`; `resumeSubscription` ustawia `active` i czyści `pause_collection` (pusta wartość); `applySubscriptionUpdate` z `paused:true` nadpisuje status na `paused`; tenant-scope (obcy trener → `SubscriptionError`). Klient Stripe mockowany. |
