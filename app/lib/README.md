# app/lib/ — logika domenowa i infrastruktura

Warstwa repozytoriów (dostęp do DB, reguły domenowe) oraz infrastruktury (auth,
storage, env, formatowanie). Trasy w `app/routes/` wołają te funkcje w loaderach
i akcjach. **Zasada tenant-scope:** funkcje przyjmują wymagany `trainerId` lub
`traineeId` i filtrują po nim — nie omijaj tego.

## Pliki w tym katalogu (moduły domenowe i pomocnicze)

| Plik | Rola / kluczowe eksporty |
|---|---|
| `authz.ts` | Reguły dostępu tenant-scope: `ownsTrainerScope`, `canRead`, `canWrite`, typ `Resource`. `canReadCatalogRow` (odczyt wiersza katalogu exercise/skill: markowy czytelny dla każdego z tej samej org, trenerski tylko dla właściciela/jego podopiecznego; zapis markowego ZAWSZE niedozwolony — fork zamiast zapisu), typ `CatalogRow`. Predykaty marki: `ownsBrandScope(user, organizationId)` (prezes własnej org), `canWriteBrandCatalogRow(user, row)` (zapis wiersza markowego przez prezesa tej samej org). |
| `trainee-access.ts` | Gate wstrzymania podopiecznego: `assertTrainerActive(db, user)` — gdy trener podopiecznego jest zdezaktywowany (`users.archived_at`), rzuca `redirect("/podopieczny/wstrzymane")`. Wspólny dla layoutu podopiecznego ORAZ tras poza layoutem (`wrapped`, `aktywuj`). |
| `env.ts` | Walidacja i leniwy dostęp do zmiennych środowiskowych (Zod): `getEnv()`, `env`, typ `Env`. Opcjonalne klucze `GOOGLE_CLIENT_ID/SECRET/REDIRECT_URI/TOKEN_ENC_KEY` + predykat `googleConfigured()`. |
| `format.ts` | Formatowanie dat/liczb zależne od locale (BCP-47, domyślnie `pl-PL` — wstecznie kompatybilne): `fmtDate`, `fmtDateShort`, `fmtDateTime` (data+godzina UTC; pl ma stały format ręczny, inne locale przez Intl), `fmtTime` (sama godzina UTC, locale-neutralne), `daysAgo` (czas względny przez `Intl.RelativeTimeFormat`); poza tym `todayISO`, `pluralizePl`; helpery miesiąca kalendarza: `monthRangeUTC` (zakres „YYYY-MM" → ISO UTC + rok/miesiąc), `shiftMonth`. Locale przekazuj z `langToIntlLocale[i18n.language]` (patrz `app/i18n/`). |
| `files.ts` | Ścieżki plików + podpisywanie URL-i HMAC: `signFileUrl`, `verifyFileUrl`, `extForMime`, `*Path`, `newFileId`, `ALLOWED_*_MIME`. |
| `file-uploads.ts` | Upload z walidacją MIME/magic-bytes/limitów + kolejka sprzątająca przy rollbacku: `uploadFile` (właściciel to `UploadOwner` = `{ trainerId }` \| `{ organizationId }` — plik trenerski lub markowy), `deleteFile*`, `UploadCleanupQueue`, `UploadError`, `ownerColumns` (helper mapujący `UploadOwner` na kolumny DB). |
| `exercises.ts` | Normalizacja tagów ćwiczeń: `normalizeTags`. |
| `categories.ts` | CRUD kategorii ćwiczeń per-trener: `listCategoriesForTrainer`, `addCategory`, `deleteCategory`, `filterToKnownCategoryNames`, `CategoryError`. |
| `plan-types.ts` | Schematy Zod formularza planu (single/superset/dropset): `PlanFormSchema`, `SessionFormSchema`, `BlockFormSchema`, `ItemFormSchema` + typy. |
| `plans.ts` | Repozytorium planów: load/list, `createBlankPlan`, `createDraftFromActive`, `saveDraftPlan`, `publishPlan`, `deletePlan`, `PlanRepoError`. Wersjonowanie i deep-clone. |
| `workouts.ts` | Treningi: aktywny plan, sesja do logowania, lista/szczegóły logów, klienci trenera, `saveWorkoutLog`, `WorkoutSaveError`. Autoryzacja widza wbudowana. `listLogsForTrainee`/`countLogsForTrainee` przyjmują `{ sort?: LogSort, q?, video? }`. `listClientsForTrainer`/`countClientsForTrainer` przyjmują `{ sort?: ClientSort, q?, plan? }`. |
| `stats.ts` | Agregacje statystyk: `getHeroStats`, `getThisWeekStats`, `getActivityHeatmap`, `getEffortBalance`, `getHealthStats`, `getPlateauExercises`, `getActivePlanSessionUsage`, `getCurrentPlanTotals`, `getVideoCoverage`, `getBodyPhotoCoverage`, `getTagDistribution`, `getExerciseProgress`, `getEasierAtSameReps`, `getSideBySidePhotoPairs`, `detectNewPRsForLog`, `computeStreak`, `computeLongestStreak`. Współdzielone trener/podopieczny. (Usunięto: `getMonthSummary`, `getTopExerciseSparklines`, `getPersonalRecords`, `MONTH_NAMES`.) |
| `wrapped.ts` | Miesięczne podsumowania "Wrapped": dostępne miesiące, `getMonthlyWrapped`, archetypy, porównanie m/m, `parseYM`/`formatYM`. |
| `body-photos.ts` | Zdjęcia sylwetki: list/count/`addBodyPhoto`/`deleteBodyPhoto`, `BodyPhotoError`. `listBodyPhotosForTrainee` przyjmuje `{ sort?: "newest"\|"oldest" }`. Sprzątanie blobów po transakcji. |
| `trainees.ts` | Usuwanie podopiecznego (kaskada + ręczne sprzątanie blobów): `deleteTraineeFully`, `assertTraineeOwnedBy`, `TraineeDeleteError`. |
| `consultation-recurrence.ts` | Czyste liczenie dat terminów z reguły cyklu (bez DB, bez `Date.now`): `nextOccurrences`, typ `RecurrenceRule`. UTC, okno `[from, from+horizonDays]`. Obsługuje weekly/biweekly (kotwica `weekday`) i monthly (`dayOfMonth` ≤28). |
| `consultation-status.ts` | Jedno źródło prawdy dla prezentacji statusu terminu (czyste, cel testów): `consultationPresentation` (etykieta+ton, świadome roli — `planned` przyszły/miniony), `mostUrgentTone` (kropka dnia), mapy `TONE_TEXT`/`TONE_DOT`, typy `ConsultationTone`/`ConsultationPresentation`. Używane przez OBA panele, by status nie wyglądał inaczej zależnie od widoku. |
| `consultation-types.ts` | Zod + czyste guardy przejść: `ScheduleFormSchema`, `ConsultationDocFormSchema`, `ActionItemFormSchema`, `TraineeActionSchema`, `ConsultationItemStatusSchema` + typy; guardy `canTraineeAct`, `canTrainerReschedule`/`canTrainerCancel`, `canDocument`. |
| `consultation-schedules.ts` | Repo harmonogramu (tenant-scope `trainerId`): `getActiveSchedule`, `upsertSchedule` (jeden aktywny na parę; regeneruje przyszłe `planned`, anuluje stare niepotwierdzone), `deactivateSchedule`, `ensureOccurrences` (idempotentna materializacja po `(schedule_id, scheduled_at)`), `defaultTitle`, stała `HORIZON_DAYS`, `ScheduleError`. |
| `consultations.ts` | Repo okazji (tenant-scope `trainerId`/`traineeId`): `listOccurrencesForTrainee` (zakres dat, pomija cancelled), `listOccurrencesForTrainer`, `listTrainerOccurrencesInRange` (zbiorczy kalendarz trenera — wszyscy podopieczni w zakresie, z `displayName`, bez cancelled), `getConsultationDetail`, `createAdhocConsultation`, `documentConsultation`, `rescheduleOccurrence`, `cancelOccurrence`, `respondToOccurrence` (confirm/decline/request_change — guardy statusów), `setActionItemStatus`, `deleteConsultation`, `countPendingForTrainee`, `nextUpcomingForTrainee`, `ConsultationError`. Helpery synchronizacji Google: `getSyncRow`, `listUnsyncedForSync`, `setGoogleEventId`, `listGoogleEventIdsForPair` (wszystkie zdarzenia pary — sprzątanie przy usuwaniu podopiecznego), `listCancelledGoogleEventIds` (nadchodzące odwołane terminy ze zdarzeniem — sprzątanie po zmianie harmonogramu), interfejsy `ConsultationSyncRow`/`GoogleEventRef`. |
| `consultation-form.server.ts` | Parsery FormData → obiekty do walidacji Zodem: `parseConsultationDocFormData` (termin/dokumentacja; punkty jako równoległe `itemBody[]`/`itemStatus[]`), `parseScheduleFormData` (reguła harmonogramu). Tylko server-side. |
| `progression-math.ts` | Czysta logika "Progresja" (bez DB): zakresy dat, agregacja tygodniowa, statusy (`statusFromSessions` komputuje z `best` — rekordu, `classifyStatus`), PR-oznaczanie (`markPrs`), % zmiana, normalizacja, sortowanie listy (`sortProgressionRows`), polski skrót jednostki (`unitLabelPl` mapuje REPS/SEC), filtrowanie wierszy po ID ćwiczenia (`excludeByExerciseId`), wybór ujęcia wykresu dla okresu (`seriesForRange` — tygodniowe dla 6m/all, ale fallback do per-sesja gdy zwinęłoby do <2 punktów, by szerszy okres nie pokazywał mniej niż węższy), typy `ProgressionListRow`, `SessionPoint`, `ChartPoint`, `ProgressionStatus`. |
| `progression.ts` | Warstwa DB dla Progresji: `loadProgressionSessions` (bazowe zapytanie per-sesja, reużywane przez Tasks 4–5; wyklucza zarchiwizowane ćwiczenia), `listProgressionExercises` (lista landing), `findTraineeOfTrainer` (tenant-scope guard → 404 gdy null), `todayIso`. `ComparisonSeries` nosi `startValue`/`endValue` (surowe best na starcie i końcu okresu; do tabeli „Konkretnie" w porównaniu). |
| `skill-progression-math.ts` | Czysta logika "Umiejętności" (bez DB): `currentLevelFromEvents` (najświeższe zdarzenie awansu → bieżący wariant), `suggestAdvancement` (miękka sugestia awansu/cofnięcia na podstawie sygnałów), typy `AdvancementEvent`, `AdvanceSignals`, `AdvancementSuggestion`, stałe `MIN_SESSIONS_FOR_SUGGESTION`, `HIGH_RPE`. |
| `skill-types.ts` | Schematy Zod walidacji formularzy umiejętności: `SkillFormSchema`, `AdvancementFormSchema`, `ReorderFormSchema`, `PrerequisiteFormSchema` + typy `SkillForm`, `AdvancementForm`, `ReorderForm`. |
| `skills.ts` | Repozytorium umiejętności na **efektywnym katalogu** (własne ∪ markowe org): `listSkillsForTrainer`, `getSkillWithVariations`, `createSkill`, `updateSkill`, `archiveSkill`, `addVariation`, `removeVariation`, `reorderVariations`, `listAssignableExercises`, `findSkillForExercise`, `listExerciseSkillMap`, `SkillError`. Prerequisite CRUD: `addPrerequisite`, `removePrerequisite`, `listPrerequisitesForSkill`, `listAssignablePrerequisites`. Funkcje odczytu efektywnego katalogu (`listSkillsForTrainer`/`getSkillWithVariations`/`listAssignableExercises`/`findSkillForExercise`/`listExerciseSkillMap`) przyjmują `{ trainerId, organizationId }` i operują na zbiorze własne ∪ markowe org (bez sforkowanych, przez `effectiveSkillWhere`); `SkillListRow`/`SkillDetail` niosą `isBrand` (badge „Marka"). Reguła „ćwiczenie należy do ≤1 umiejętności w efektywnym widoku" egzekwowana w repo (`addVariation` — globalny `UNIQUE(exercise_id)` usunięty); ON DELETE RESTRICT na awansach jako przyjazne błędy. `addVariation` odrzuca zarchiwizowane ćwiczenie; `removeVariation` przepakowuje `ordinal` (bez dziur); `archiveSkill` czyści krawędzie prerekwizytów w transakcji; `findSkillForExercise` zwraca aktywną umiejętność, której ćwiczenie jest wariantem (blokada archiwizacji ćwiczenia-wariantu). |
| `skill-tree.ts` | Repozytorium drzewa umiejętności na efektywnym katalogu: `getSkillTreeForTrainer` (szkielet DAG dla autora), `getSkillTreeForTrainee` (drzewo z per-podopieczny stanami węzłów); oba + `loadGraph` przyjmują `{ trainerId, organizationId }`, a krawędzie są efektywne (własne ∪ markowe org); typy `TreeNode`, `SkillTree`. |
| `skill-tree-math.ts` | Czysta logika drzewa prerekwizytów (bez DB): `wouldCreateCycle`, `assignLayers`, `orderWithinLayer`, `nodeState`, `topoOrder`, `layoutNodes` (oblicza pozycje SVG węzłów — współdzielone przez `skill-tree.ts` i `brand-catalog.ts`); typy `Edge`, `NodeState`. |
| `skill-progression.ts` | Repozytorium postępów umiejętności: `getSkillMapForTrainee` (mapa wszystkich umiejętności trenera z bieżącym wariantem podopiecznego, historią i opcjonalną sugestią awansu), `setStartingLevel` (pierwszy wpis: fromVariationId = null), `recordAdvancement` (awans/cofnięcie; sprawdza "no start" i "same level"). Współdzielone trener/podopieczny. |
| `organizations-types.ts` | Schematy Zod dla modułu organizacji: `RegionInputSchema` (walidacja country/currency/locale dla wspieranych rynków), typ `RegionInput`. |
| `organizations.ts` | Funkcje DB bootstrapu tenancy marki: `ensureOrganization` (singleton), `ensureRegion` (idempotentne po org+country), `assignUserToOrgRegion`, `ensureBrandAdmin` (idempotentne po email); interfejs `EnsureBrandAdminInput`. |
| `catalog.ts` | Warstwa DB efektywnego katalogu ćwiczeń (własne ∪ markowe org − już sforkowane): `forkedExerciseOriginIds` (origin_id markowych ćwiczeń sforkowanych przez trenera), `effectiveExerciseWhere` (warunek WHERE łączący własne i markowe organizacji z pominięciem sforkowanych — `forkedOriginIds` liczony raz przez trasę), `isBrandOwned` (badge „Marka"), `forkExercise` (copy-on-write markowego ćwiczenia na własność trenera z `origin_id`; idempotentny — zwraca id istniejącego forka; null gdy origin nie jest markowy lub spoza org trenera → 404), analogiczne dla umiejętności `forkedSkillOriginIds`/`effectiveSkillWhere`, `forkSkill` (głęboki klon markowej umiejętności w jednej transakcji: skill + warianty + krawędzie prereq z podmianą skillId na nowy klon przez `planSkillClone`; idempotentny i race-safe na `skills_trainer_origin_uniq`; null gdy origin nie jest markowy lub spoza org trenera → 404), `promoteTrainerCatalogToBrand` (promuje cały własny kanon trenera — niesforkowane ćwiczenia/umiejętności `origin_id IS NULL` + jego krawędzie prereq — do poziomu marki IN PLACE: `trainer_id=NULL, organization_id=org` bez zmiany `id`, więc FK z planów/logów/wariantów/awansów pozostają ważne; idempotentny — wiersze już markowe pomijane; jedna transakcja), `resolveCatalogOrgId`, `fileIsBrandDemoInOrg`, `CatalogError`. Czyste helpery transformacji w `catalog-math.ts`. |
| `catalog-math.ts` | Czysta logika katalogu (org/marka ↔ trener), bez DB/I/O: `suppressForkedOrigins` (filtruje markowe wiersze po sforkowanych origin), `exerciseAlreadyVariationInView`, `planSkillClone` (plan głębokiego klonu drabiny: warianty + krawędzie prereq z podmianą skillId); typy `CloneVariationInput`, `ClonePrereqInput`. |
| `brand-catalog.ts` | Repozytorium katalogu markowego dla prezesa (`brand_admin`). Wszystkie funkcje przyjmują `organizationId` i operują wyłącznie na wierszach `trainer_id IS NULL AND organization_id = org`; obcy/inno-org zasób → `null`/404. Ćwiczenia markowe: `listBrandExercises`, `getBrandExercise`, `createBrandExercise`, `updateBrandExercise`, `archiveBrandExercise`, `restoreBrandExercise`. Umiejętności i warianty: `createBrandSkill`, `updateBrandSkill`, `archiveBrandSkill`, `addBrandVariation`, `removeBrandVariation`, `reorderBrandVariations`, `findBrandSkillForExercise`, `listAssignableBrandExercises`. Prerekwizyty i drzewo: `addBrandPrerequisite`, `removeBrandPrerequisite`, `listBrandPrerequisitesForSkill`, `listAssignableBrandPrerequisites`, `getBrandSkillTree`. Reużywa czystych helperów `skill-tree-math`; `skills.ts` trenera pozostaje nienaruszone. Typ błędu: `BrandCatalogError`. |
| `ambassadors.ts` | Repozytorium ambasadorów (trenerzy w org) dla prezesa (`brand_admin`). Wszystkie funkcje org-scoped — trener spoza org → `null`/404. Eksporty: `listAmbassadors` (lista z metrykami: aktywni podopieczni, logi 7/30d, MRR), `getAmbassadorProfile` (profil + metryki), `inviteAmbassador` (sprawdza region w org → `createInvite` z `targetRole:"trainer"`), `deactivateAmbassador`/`reactivateAmbassador` (ustawia/czyści `users.archived_at` + best-effort pauza/wznowienie subskrypcji podopiecznych trenera), `AmbassadorError`. |
| `ambassador-types.ts` | Schematy Zod dla modułu ambasadorów: `AmbassadorInviteSchema` (walidacja `displayName`/`email`/`regionId`; komunikaty jako klucze i18n). |
| `list-params.ts` | Parser i helper dla kontrolek list (sortowanie, filtrowanie, szukajka): `parseListControls`, `buildControlHref`, typy `ListControlsSpec`, `ListControlsState`, `SortOption`, `FilterGroup`, `FilterOption`. |
| `money.ts` | Obsługa waluty PLN: `fmtMoney` (grosze → "123,45 zł"), `parsePlnToGrosze` (string z PLN → grosze lub null), `MonthlyAmountSchema` (Zod; min 200 gr, max 10 000 000 gr, int). |
| `payments.ts` | Księga płatności (`subscription_payments`, tenant-scope): `recordInvoice` (upsert po `stripe_invoice_id` — idempotencja webhooka), `listPaymentsForTrainee` (po `traineeId`), `listPaymentsForPair` (po `trainerId`+`traineeId`); typ `InvoiceRecord`. |
| `rate-limit.ts` | In-memory rate-limiting (fixed-window, per-IP) dla tras wrażliwych: `fixedWindowHit` (czysta logika okna), `InMemoryRateLimitStore` (za interfejsem `RateLimitStore`; wstrzykiwany `now`+`sweepThreshold`, sweep wygasłych), `clientIp` (leftmost z `X-Forwarded-For`, brak → `"unknown"`), `enforceRateLimit` (fail-open), `resetRateLimit`, `rateLimited` (`data()` → 429 + `Retry-After` + komunikat PL), stała `RATE_LIMITS` (login/invite: 10 prób / 15 min). Używane w `routes/login.tsx` i `routes/zaproszenie.$token.tsx`. |
| `logger.ts` | Structured logging (JSON-lines → stdout/stderr): `logger.{info,warn,error}(event, ctx?)`, czysta `formatLogLine` + `errorMeta` (whitelist `name`+`code`, NIGDY `message`/sekretów; płytka auto-redakcja wartości `Error` w ctx), `logUnhandled(error, request)` (logika hooka `handleError` z `entry.server.tsx`; pomija anulowane żądania). Logger nigdy nie rzuca (fallback przy błędzie serializacji). |
